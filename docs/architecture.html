System Architecture

TherapOS is a Turborepo monorepo with a Next.js frontend and NestJS API. PostgreSQL with pgvector handles relational data and vector search. All AI calls are non-blocking — the product works without AI as a graceful fallback.

Key Architectural Decisions

1. Monolith First, Microservices Later

The NestJS API is a single deployable unit. AI processing, search, and CRUD are all in one service. The benefit: simpler debugging, shared transactions, one deployment target.

Extract the AI module into a separate service only when you need independent scaling — typically at ~10,000 active users where AI inference is the bottleneck. The NestJS module boundary makes this extraction clean.

2. pgvector Over Pinecone for MVP

Pinecone adds infrastructure complexity (another service to manage, another cost center) and an extra network hop. pgvector in PostgreSQL handles millions of embeddings efficiently with HNSW indexing, with the added benefit that row-level therapist isolation is enforced at the database layer.

Migration trigger: If note embedding count exceeds 500k, or if metadata filtering requirements become complex enough that raw pgvector queries are difficult to maintain, migrate to Pinecone. The search/ NestJS module is the only code that changes.

3. SSE Over WebSockets for AI Streaming

AI note generation streams token-by-token to the frontend using Server-Sent Events. SSE is simpler than WebSockets for one-directional streaming (server → client), works through HTTP/2 without special infrastructure, and requires no WebSocket server management.

The frontend uses a custom useAiStream hook that manages the EventSource lifecycle, error handling, and reconnection. When the stream ends, the full JSON note object is returned in the final event.

4. BullMQ for All Post-Finalization Jobs

Note generation itself streams directly. But the post-finalization memory pipeline (embedding and summary refresh) runs entirely via BullMQ jobs. Benefits: the therapist sees "Finalized" immediately, jobs are retried on failure, job history is inspectable.

Two queues: note-embeddings and patient-summaries. Both use Redis as the queue backend. Summary refresh is chained to fire after embedding completes (not in parallel) to ensure the embedding is available when the summary is generated.

5. Row-Level Therapist Isolation in Every Query

Every Prisma query that touches a Patient, Session, Note, Goal, or Homework record filters by therapistId = authenticatedUserId. This is enforced in the service layer — not just the controller layer — to prevent accidental cross-therapist data exposure. Automated tests verify that therapist A cannot access therapist B's data even with a valid JWT.

Route Structure

All routes require authentication (Clerk middleware). Unauthenticated requests redirect to the Clerk sign-in page. The App Router's layout hierarchy: Root Layout → Auth Layout → Dashboard Layout → Patient/Session Layout. Streaming (React Suspense) is used on session pages for the AI prep brief.

Access Control

  • Authentication: Every API endpoint is guarded by ClerkGuard — verifies JWT signature, extracts therapistId, rejects expired or malformed tokens.
  • Authorization: Every patient/session/note query filters by therapistId = req.user.id. A valid JWT for therapist A cannot retrieve therapist B's data — enforced in service layer, verified by automated tests.
  • MFA: Enforced via Clerk for all accounts. Cannot be disabled by users. Reminder in onboarding flow.
  • Rate limiting: AI endpoints — 20 requests/minute per user. General API — 200 requests/minute per user. Redis-backed.

Audit Logging

A NestJS interceptor runs on every request that touches PHI. For each such request, it writes an AuditLog row containing: userId, patientId (if applicable), action verb (PATIENT_VIEWED, NOTE_CREATED, AI_GENERATED, etc.), resource type, resource ID, IP address, user agent, timestamp.

Audit logs are retained for 6 years per HIPAA requirements. After retention expires, logs are permanently deleted. The createdAt index ensures efficient time-range queries. Therapists can view their own audit log in Settings → Privacy → Audit Log.

Business Associate Agreements

Target state — no BAA has been executed yet. A BAA is required with every vendor that may process PHI. The "BAA status" column below shows what each vendor offers, not what has been signed. OpenAI and Anthropic BAAs are conditional on zero-retention-eligible usage and approval.

⚠
PostHog and Sentry receive zero PHI

Analytics (PostHog) and error monitoring (Sentry) are deliberately excluded from the BAA list because they never receive PHI. The HIPAA audit interceptor explicitly strips all patient-identifying data before any event is sent to these services. This is verified in CI.

BullMQ Job Details

JobQueueTriggerWhat it doesRetries
embed-notenote-embeddingsNote finalizedConcatenate note fields → OpenAI embedding API → upsert NoteEmbedding with vector3x with exp. backoff
refresh-summarypatient-summariesAfter embed-note completesFetch last 3 notes + old summary → Claude Haiku → update Patient.aiSummary3x with exp. backoff

Jobs are chained: refresh-summary fires in the embed-note completion callback. If embed-note fails after 3 retries, refresh-summary does not fire for that session. The summary is regenerated on the next successful note finalization. This is an acceptable tradeoff — the summary is eventually consistent, not strongly consistent.
