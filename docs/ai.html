Context Assembly Pipeline

Every AI call starts by assembling a PatientContext object. This is the most important function in the codebase — what goes in determines what comes out.

async buildPatientContext(patientId, sessionId?) {
  const [patient, goals, recentSessions, latestHomework] = await Promise.all([
    prisma.patient.findUnique({ where: { id: patientId } }),
    prisma.goal.findMany({
      where: { patientId, status: 'ACTIVE' },
      orderBy: { createdAt: 'asc' }
    }),
    prisma.session.findMany({
      where: { patientId, status: 'COMPLETED' },
      include: { note: true },
      orderBy: { scheduledAt: 'desc' },
      take: 5  // last 5 sessions only
    }),
    prisma.homework.findMany({
      where: { patientId },
      orderBy: { createdAt: 'desc' },
      take: 3
    }),
  ])

  return {
    patient: {
      firstName: patient.preferredName || patient.firstName,
      modality: patient.modality,
      concerns: patient.primaryConcerns,
      diagnoses: patient.diagnoses,
      aiSummary: patient.aiSummary,   // rolling summary
    },
    goals: goals.map(g => ({ title: g.title, status: g.status })),
    recentSessions: recentSessions.map(s => ({
      sessionNumber: s.sessionNumber,
      date: s.scheduledAt,
      note: truncateNote(s.note, 400),  // budget: 400 tokens per note
    })),
    latestHomework: latestHomework.map(h => ({
      title: h.title, status: h.status, assignedAt: h.createdAt,
    })),
  }
}

Prompt Templates

Session Prep Brief

You are an AI assistant helping a licensed {modality} therapist prepare for a session. You are NOT a therapist. You are a preparation tool. Never diagnose. Never prescribe. Never make clinical decisions. THERAPIST CONTEXT: Modality: {modality} | License: {licenseType} PATIENT: {firstName} | Session #{sessionNumber} Primary concerns: {concerns} Active diagnoses: {diagnoses} AI SUMMARY (rolling): {aiSummary} ACTIVE GOALS: {goals} LAST {n} SESSIONS (newest first): {recentSessionNotes} HOMEWORK (last assigned): Title: {hwTitle} | Status: {hwStatus} Generate a session preparation brief. Return exactly this JSON structure: { "recap": "2-3 sentences: what happened last session, key themes", "suggestedQuestions": ["Q1", "Q2", "Q3", "Q4"], "homeworkFollowUp": "how to check in on the homework", "patterns": "notable cross-session pattern, or null if none" } Rules: - Questions must match the therapist's modality - Be concise — this is a 90-second pre-read - If information is missing, work with what you have - Never mention medication, diagnosis codes, or legal matters

SOAP Note Draft

You are an AI assistant helping a licensed therapist draft a SOAP progress note. This is a DRAFT. The therapist will review and edit before finalizing. Never fabricate clinical details not present in the therapist's raw notes. PATIENT: {firstName} | Session #{sessionNumber} | {date} MODALITY: {modality} | CONCERNS: {concerns} RECENT CONTEXT (for continuity — do not copy verbatim): {recentContext} THERAPIST'S RAW NOTES FROM THIS SESSION: --- {rawNotes} --- Draft a professional SOAP progress note. SOAP FORMAT: - Subjective: What the patient reported (patient's own experience) - Objective: Therapist's behavioral observations (affect, presentation, engagement) - Assessment: Clinical synthesis (progress toward goals, session themes) - Plan: Next steps (homework, referrals, next session focus) STRICT RULES: 1. Only use information from the raw notes above 2. If information is missing, write "[Therapist to complete]" 3. Keep each section to 2-4 sentences 4. Never fabricate quotes, events, or observations 5. Do not include diagnosis codes 6. Do not mention AI or this process in the note Return JSON: {"subjective":"...","objective":"...","assessment":"...","plan":"..."}

Homework Generator

You are helping a {modality} therapist generate homework for their patient. PATIENT: {firstName} SESSION THEMES: {sessionThemes} ACTIVE GOALS: {goals} MODALITY: {modality} PREVIOUS HOMEWORK: {previousHomework} Generate 3 homework options. Each must be concrete, actionable, and appropriate to the stated modality. Return JSON: {"options": [ { "title": "...", "description": "detailed instructions for the patient", "category": "journaling|behavioral|exposure|mindfulness|social", "rationale": "why this fits the session themes and modality" } ]}

Patient Summary (Rolling — runs after every finalized note)

You are updating a rolling clinical summary for a therapist's reference. This summary is for the therapist only — not part of the official record. PATIENT: {firstName} | Total sessions: {sessionCount} PREVIOUS SUMMARY: {previousSummary} NEWEST SESSION NOTE (Session #{sessionNumber}): {latestNote} Update the summary to reflect the newest session. Keep it: - 3-5 sentences maximum - Focused on patterns, progress, and current clinical picture - Written for a therapist who knows this patient well - Clinically accurate but not diagnostic Return only the updated summary text. No JSON wrapper.

Memory Architecture (Three Tiers)

Tier 1 — Redis

Active session state, prep brief cache, in-progress note draft. TTL: 24h. Fast read during live sessions.

Tier 2 — PostgreSQL

Rolling 3–5 sentence AI summary per patient. Updated after every finalized note. Injected into every AI call.

Tier 3 — pgvector

Every finalized note embedded (text-embedding-3-small). Searched via cosine similarity for NL search and deep context.

Memory Update Flow

Therapist clicks "Finalize Note"
  │
  ├─► Lock note in DB (isFinalized = true, finalizedAt = now)
  │
  ├─► BullMQ: 'embed-note' job
  │     │
  │     ├─► Get note text (all fields concatenated)
  │     ├─► Chunk: 512-token windows, 64-token overlap
  │     ├─► OpenAI text-embedding-3-small → 1536d vector
  │     └─► Upsert NoteEmbedding row with pgvector
  │
  └─► BullMQ: 'refresh-summary' job (after embed completes)
        │
        ├─► Fetch last 3 finalized notes + previous aiSummary
        ├─► Call Claude Haiku: "Update rolling summary"
        └─► patient.aiSummary = result, aiSummaryUpdatedAt = now

AI Behavioral Rules (Baked into Every Prompt)

  • Never diagnose. No DSM codes, no clinical diagnoses in AI outputs.
  • Never fabricate. If the therapist's raw notes don't mention something, the AI doesn't either. Missing fields get "[Therapist to complete]".
  • Always a draft. Every output is explicitly framed as a draft for therapist review.
  • Modality-aware. Suggested questions and homework always respect the therapist's stated modality (CBT, DBT, psychodynamic, etc.).
  • Risk nudge only. If note content contains language suggesting imminent risk, the AI surfaces a soft nudge: "Content may warrant a safety review." — never a diagnosis, never an alarm.
  • First-session aware. When there is no prior history, the AI explicitly says so rather than generating generic filler.
