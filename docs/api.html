API Reference

All endpoints are prefixed /api/v1. Authentication uses a Clerk JWT in the Authorization: Bearer header. All responses follow a consistent envelope. Errors include a typed errors array.

Base URL & Authentication

Base URL:  https://api.therapos.com/api/v1
Auth:      Authorization: Bearer <clerk_session_token>
Content:   Content-Type: application/json

Get the session token from Clerk's client SDK:

// React / Next.js
import { useAuth } from '@clerk/nextjs'
const { getToken } = useAuth()
const token = await getToken()

// curl example
TOKEN=$(clerk session token)
curl -H "Authorization: Bearer $TOKEN" https://api.therapos.com/api/v1/patients

Response Envelope

// Success
{
  "data": { ... } | [...],
  "meta": {          // Present on paginated responses
    "page": 1,
    "limit": 20,
    "total": 47,
    "pages": 3
  }
}

// Error
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "errors": [
    { "field": "firstName", "message": "Required" },
    { "field": "primaryConcerns", "message": "Must be an array" }
  ]
}

Create patient

POST /patients
Body:
{
  "firstName": "Maya",           // Required
  "lastName": "Chen",
  "preferredName": "Maya",
  "dateOfBirth": "1990-04-15",   // ISO 8601 date
  "email": "maya@example.com",
  "phone": "+1-555-0100",
  "primaryConcerns": ["anxiety", "workplace stress"],
  "diagnoses": ["F41.1"],
  "modality": "CBT",             // Overrides therapist default for this patient
  "sessionFreq": "weekly"        // "weekly" | "biweekly" | "monthly"
}

// curl
curl -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Maya","primaryConcerns":["anxiety"]}' \
  https://api.therapos.com/api/v1/patients

// Response: 201 Created
{ "data": { "id": "clx...", "firstName": "Maya", ... } }

Discharge patient

// Soft-delete: sets status = DISCHARGED, endDate = now()

// Response: { "data": { "success": true } }

Notes

Get note

GET /sessions/:sessionId/note
// Returns SessionNote or 404 if not yet created

Save note (create or update)

POST /sessions/:sessionId/note
Body (SOAP):
{
  "format": "SOAP",
  "subjective": "Patient reported continued anxiety...",
  "objective": "Patient presented alert and engaged...",
  "assessment": "Patient continues to make progress...",
  "plan": "Continue breathing practice..."

Body (DAP):
{
  "format": "DAP",
  "data": "Patient reported and therapist observed...",
  "dapAssessment": "Clinical synthesis...",
  "dapPlan": "Next steps..."
}

// Response: 200 OK — full note object with aiGenerated flag

Finalize note

POST /sessions/:sessionId/note/finalize
// Requires: note must exist and not already be finalized
// Effect:
//   - isFinalized = true, finalizedAt = now()
//   - BullMQ: queues 'embed-note' job (async)
//   - BullMQ: queues 'refresh-summary' job (after embed)
//   - AuditLog: NOTE_FINALIZED action recorded
// Returns immediately — embedding/summary happen async

// Response: 200 OK
{
  "data": {
    "success": true,
    "note": { "id": "clx...", "isFinalized": true, "finalizedAt": "..." }
  }
}

AI Endpoints

⚠
Rate limits on AI endpoints

AI endpoints are rate-limited to 20 requests/minute per user. Exceeding this returns 429 with a Retry-After header.

Generate session prep brief

POST /ai/prep/:sessionId
// Generates AI prep brief from patient context
// Cached in Redis for 24h — subsequent calls return cached version
// To force regeneration, add ?force=true

// Response: Server-Sent Events (SSE) stream
// Content-Type: text/event-stream

// Events during streaming:
data: {"type":"delta","content":"Maya focused on..."}
data: {"type":"delta","content":" workplace anxiety"}
// ... more deltas
// Final event:
data: {"type":"done","result":{
  "recap": "Maya focused on workplace anxiety last session.",
  "suggestedQuestions": ["How was work this week?", "..."],
  "homeworkFollowUp": "Check in on breathing log...",
  "patterns": "Anxiety correlates with evaluation events"
}}

// Frontend usage:
const source = new EventSource('/api/v1/ai/prep/' + sessionId)
source.onmessage = (e) => {
  const { type, content, result } = JSON.parse(e.data)
  if (type === 'delta') updateStreamingText(content)
  if (type === 'done') { setPrep(result); source.close() }
}

Generate AI note draft

POST /ai/note/draft
Body: { "sessionId": "clx...", "format": "SOAP" | "DAP" | "BIRP" | "FREE" }

// Prerequisites: session must have rawNotes set
// Response: SSE stream

// Stream events:
data: {"type":"delta","field":"subjective","content":"Patient reported..."}
data: {"type":"delta","field":"objective","content":" continued anxiety"}
// ... fields stream in order: subjective, objective, assessment, plan
// Final event:
data: {"type":"done","result":{
  "subjective": "Patient reported continued workplace anxiety...",
  "objective": "Patient presented alert and engaged...",
  "assessment": "Patient continues to make progress...",
  "plan": "Continue breathing practice..."
}}

// On error (AI provider unavailable):
data: {"type":"error","message":"AI service temporarily unavailable. Your notes are saved."}

// curl (for testing — SSE doesn't work great with curl, use -N flag):
curl -N -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"clx...","format":"SOAP"}' \
  https://api.therapos.com/api/v1/ai/note/draft

Search

Natural language search

GET /search?q=query&patientId=optional_patient_id&limit=10

// Examples:

Webhooks (Internal)

//   user.created → create User row with therapistId = clerkId
//   user.updated → sync name, email
//   user.deleted → soft-delete (audit logs retained, PHI removed)

// Verified via Stripe webhook signature
// Events handled:
//   customer.subscription.created → update Subscription row

//   customer.subscription.deleted → cancel, set status = CANCELLED
//   invoice.payment_failed → set status = PAST_DUE, trigger email

Error Reference

StatusCodeCauseResolution
400Bad RequestZod validation failure — body or query params invalidCheck errors array for field-level detail
401UnauthorizedMissing or expired Clerk JWTCall getToken() to refresh and retry
403ForbiddenAuthenticated but accessing another therapist's resourceVerify resource ownership — check patient/session IDs
404Not FoundResource not found or not owned by this therapistVerify resource ID and that it belongs to the authenticated therapist
409ConflictDuplicate unique constraint — e.g., session number already exists for patientCheck the conflict details in the error message and use a different value
422UnprocessableBusiness logic failure — e.g., finalizing an already-finalized noteRead the error message for the specific rule violation
429Rate LimitedAI endpoints: >20 req/min. General: >200 req/minRespect the Retry-After header value (seconds)
500Internal ErrorUnhandled exception — captured in SentryCheck Sentry for stack trace. Include the X-Request-ID response header when reporting
503Service UnavailableAI provider (Anthropic/OpenAI) unavailableProduct continues to function without AI. Retry AI calls after delay. Notes auto-saved.

Pagination

Paginated endpoints accept ?page=N&limit=M query params. Default: page=1, limit=20. Maximum limit=100. Responses include a meta object with page, limit, total (total matching records), and pages (total pages).
